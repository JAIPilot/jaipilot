# Support

## Start with the right channel

- **Usage question or project fit:** start a
  [GitHub Discussion](https://github.com/JAIPilot/jaipilot/discussions).
- **Reproducible product defect:** open a
  [bug report](https://github.com/JAIPilot/jaipilot/issues/new?template=bug_report.yml).
- **Workflow or capability proposal:** open a
  [feature request](https://github.com/JAIPilot/jaipilot/issues/new?template=feature_request.yml).
- **Performance regression:** use the
  [performance report](https://github.com/JAIPilot/jaipilot/issues/new?template=performance_report.yml).
- **Security vulnerability:** follow [SECURITY.md](SECURITY.md); never disclose it in a public issue.

## Information that helps

Include the JAIPilot version, host tool and version, operating system and architecture, Java
version, Maven or Gradle version, project shape, exact request or runner operation, and the
structured JAIPilot result. Remove secrets and proprietary source before sharing logs or fixtures.

For build or coverage failures, include whether the project wrapper succeeds without JAIPilot and
whether JaCoCo XML is produced by a clean build.

## Scope

Community support is best-effort. JAIPilot can diagnose its repository scope, deterministic evidence,
proof receipt, MCP, hooks, and dashboard behavior. Project-specific build failures or host-agent
behavior may require a minimal reproduction to separate the boundaries.

The host agent may offer to open an issue when a structured JAIPilot failure appears to be a product
defect, but it must ask first. Never upload source, prompts, credentials, environment values,
proprietary paths, or unsanitized logs.
