# JAIPilot

JAIPilot gives Codex and Claude Code six focused Java engineering skills plus authenticated,
disposable Java build hardware. The customer's coding agent remains the only planner and editor.

Use it to add meaningful tests, remove proved waste, reduce real complexity, review risky diffs,
measure performance, evaluate compatible upgrades, and offload substantial Maven or Gradle work. The
remote environment includes JDK 17/21/25, Maven 3.9.16, and Gradle 9.7.0.

On the first remote call, sign in at jaipilot.com through the host's OAuth flow. The plugin contains
no shared secret, provider credential, GitHub App dependency, local adapter, or downloaded runtime.
The agent explicitly uploads tracked and unignored working-tree files, chooses every command,
collects durable status and logs, and destroys the workspace. Remote edits are never synchronized,
committed, pushed, or published.

Why use it: Java-specific guardrails reduce drift, ready hardware removes machine setup, current
dirty work can be verified, long commands survive disconnects, and every result must explain its
evidence and concrete benefit. In the version 6.0.0 acceptance, default Codex OAuth succeeded
without a shared secret, an uncommitted Petclinic marker appeared in the remote workspace, the
preinstalled JDK ran its 75-test clean Maven build with no failures or errors, durable IDs recovered
status and logs, cancellation worked, and workspace deletion was confirmed. This proves sign-in,
current-change transport, readiness, durability, and cleanup; it is not an unmeasured speed claim.

Learn more at <https://github.com/JAIPilot/jaipilot>.
